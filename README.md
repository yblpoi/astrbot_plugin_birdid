# AstrBot 鸟类识别插件

对接懂鸟 v2 协议的鸟类识别服务，在聊天里直接认鸟。用户把照片或录音发进来，配一句「这是什么鸟」
这类常见说法时插件直接处理、不经过模型；说法冷门时由模型判断意图再调用 `identify_bird` 工具。
两条路都由插件直接请求识别接口，把中文名／英文名、裁剪后的鸟图或声谱图发回聊天——整个过程
模型看不到图片，也不会去猜物种名。

- 常用指令：`/识鸟`（含「这是什么鸟」「啥鸟」等别名）—— 常见说法直接识别，不经过模型、不花 token
- LLM 工具：`identify_bird` —— 冷门或复杂说法由模型按意图调用，识别当前消息里的图片或录音
- 管理员命令：`/识鸟状态` —— 查看后端、内存、模型与开关状态
- 管理看板：识别统计、负载与内存，并可直接改设置（只有开关和选项）
- 依赖：AstrBot v4.0.0 及以上、一个可访问的懂鸟协议后端；音频处理需要 `ffmpeg`

## 特性

- **常见说法不花 token**：`识鸟`、`认鸟`、`这是什么鸟`、`啥鸟` 等十几种说法由指令过滤器直接接管，
  事件根本不会送到模型；只有说法冷门（例如「帮我看看这只在云南拍的小绿鸟」）才交给模型判断意图。
- **意图触发，不走视觉大模型**：交给模型的那部分由 `identify_bird` 工具完成。模型只负责听懂意图，
  图片与录音由插件自己上传给识别后端，模型既不接收图片也不会编造物种名。
- **图片与录音都支持**：直接发附件，或引用一条带图片/录音的消息。
- **自动回复可关**：开关打开时，聊天里直接发来的图片或录音会被插件接管自动识别；关掉后不再自动
  接管，但指令与模型工具照常可用，不带这些说法的附件则原样交给模型。
- **白名单可控**：群聊与私聊各有一个白名单开关，打开后只识别名单里的会话（名单为空表示谁都不识别）。
  看板里可以直接从机器人已加入的群聊、已有私聊里勾选。
- **中英对照**：后端对鸟类只给学名，插件用内置名称表折算成「中文名 / English / 学名」；
  名称表合并了两个公开名录，覆盖 11587 条，中文命中率 99% 以上。
- **门禁结论一句话**：回复只用一行「识别结果：鸟类（30.5%）」交代检测结果，坐标不进展示。
- **一条回复只带一张图**：图片只裁剪置信度最高的那个目标，录音只给一张声谱图（900×420，
  纯 numpy 绘制）。图编码成 JPEG，通常几十到一百多 KB。
- **输出处理时长**：每次回复末尾都有 `耗时 xx ms`。
- **不泄露内部信息**：回复和日志里不会出现模型名、设备名、文件路径或后端地址。
- **异步并发 + 忙时拒绝**：插件侧有在途配额与排队上限，等待超过 `queue_timeout_s` 立刻回「现在有点忙」，
  不排队堆积。
- **归档可关**：归档写入的图片和音频压缩进 `tar.gz`，按天数和总体积轮转；关掉归档后记录不落盘
  （阅后即焚），但统计照旧。

## 安装

1. 把整个目录放进 AstrBot 的插件目录（容器部署时放进映射出来的 `data/plugins/`）：

   ```bash
   git clone https://github.com/yblpoi/astrbot_plugin_birdid
   mv astrbot_plugin_birdid /path/to/AstrBot/data/plugins/
   ```

2. 安装依赖（AstrBot 用的解释器或容器）：

   ```bash
   pip install -r requirements.txt
   ```

3. 在 AstrBot 管理面板启用插件，然后在插件配置里填后端地址。

4. 重启 AstrBot 或重载插件。启动日志出现 `Bird identification plugin ready with N names.`
   就说明名称表加载成功；同时会看到 `added LLM tool: identify_bird`。

插件只用 AstrBot 的通用事件与消息链接口，不绑定具体适配器：`aiocqhttp`、`qq_official`
（含 `qq_official_webhook`）、`wechat_native` 都已实测可用，其它平台只要能收发图片与录音消息即可。

### 后端要求

插件的默认后端是 `http://127.0.0.1:8080`，即本机跑的懂鸟协议服务。该服务需要：

- `POST /dongniao` 接受 `image` / `sound` multipart 上传，返回 `[code, payload]`；
- `GET /healthz` 返回 `{"status": ..., "version": ..., "pending": ..., "max_queue": ...}`；
- 异步受理：先回 `[1001, resultid]`，再轮询 `resultid` 拿最终结果。

如果后端跑在另一台机器或 Docker 容器里，把 `backend_url` 改成插件**能访问到**的地址。
AstrBot 以 Docker 部署、后端跑在宿主机时，容器里写 `127.0.0.1` 指向容器自身，需要改成宿主机在
容器网桥上的地址（一般是 `172.18.0.1`，可用 `docker network inspect <网络名>` 确认）。

### 与懂鸟官方 API 的兼容性

客户端按懂鸟 v2 官方协议实现，默认参数即可直接对接 `https://ai.open.hhodata.com/api/v2`：

| 能力 | 说明 |
| --- | --- |
| 图片识别 | `image` + `upload=1`，支持 `class` 类别过滤、`area` 地区码、`did` 设备标识 |
| 图片 URL | `url` 提交，由服务端下载后识别 |
| 鸟鸣识别 | `sound` + `upload=1`，兼容官方返回的 `{duration, summary, splits}` 字典与自建服务的数组 |
| 鸟鸣 URL | `sound_url` 提交 |
| 百科资料 | `animalid` + `class` 查询物种百科 |
| 配额查询 | `quota=1`，兼作官方接口的存活探测；看板目前不展示额度数字 |
| 错误码 | 1001 处理中、1002 音频异常、1007 配额/限流、1008 无目标框、1009 地区码、1010 未识别、1011 物种不在地区 |

官方接口没有 `/healthz`，插件因此不能只靠健康检查判断后端是否存在。启动后与每次查询状态时，
插件在拿不到 `/healthz` 的情况下会再发一次免配额的 `quota=1` 探测：能应答就是官方接口，
`识鸟状态` 与看板把状态显示为「官方」；连探测都失败才显示「离线」。探测结果缓存 30 秒。
所以对接官方时看到「官方」是正确的，识别本身照常工作。

## 使用方法

### 常用说法：直接识别，不花 token

发图片或录音时配一句常见说法，插件会当成指令直接处理，这条消息不会进入模型，也不消耗 token：

```
（发一张鸟的照片）
这是什么鸟

（发一段鸟叫录音）
识鸟 云南 西双版纳
```

`识鸟` 是主指令，下面这些别名等价：`认鸟`、`辨鸟`、`识别鸟`、`识别一下鸟`、`帮我认鸟`、
`帮我识别鸟`、`鸟种识别`、`识别鸟类`、`这是什么鸟`、`这什么鸟`、`这是啥鸟`、`什么鸟`、
`啥鸟`、`看看这是什么鸟`。

指令后面跟的文字会被当成地点提示（例如 `识鸟 云南 西双版纳`），作用与工具的 `location` 参数相同：
只说地点、不带别的语法，插件会把它映射成后端地区码，叠加上地理季节先验。

匹配规则是「整条消息等于指令」或「指令后面跟一个空格再跟其它内容」，所以「这是什么鸟这么吵」
这类带别的话的说法**不会**被指令接走，仍然交给模型处理——语义能力没有丢。

指令同样受白名单与后端可用性约束：不在白名单里会回「这个会话没有开启鸟类识别。」并终止事件；
后端不可用会回「鸟类识别暂时不可用，请联系管理员。」。

### 冷门说法：交给模型（LLM 工具）

说法不固定时（例如带上了拍摄地点、或者问得很绕），消息会正常进入模型，由模型判断要不要识别：

```
（发一张鸟的照片）
帮我看看这只在云南西双版纳拍到的小绿鸟是什么

（发一段鸟叫录音）
帮我听听这是哪种鸟，我在云南拍的
```

模型识别到意图后调用 `identify_bird`，可以带一个可选的 `location` 参数（用户明确说了地点才填）。
地点用于叠加地理季节先验，提高同域近似种的分辨率；插件只映射后端**确实有坐标**的地区，
没有坐标的省份会被忽略而不是硬掰到省会，此时回复里不会出现「地点先验」这一行。

### 自动回复

`auto_reply` 打开（默认）时，聊天里直接发来的图片或录音不需要任何命令就会被识别，回复发出后
终止事件，模型不会收到这条消息；关掉之后插件不再自动接管，只有指令或模型调用 `identify_bird` 才识别。

自动回复与指令互不影响：`auto_reply` 关掉后 `/识鸟` 之类的指令照样能用（只不过这时没带附件的话
会收到一句提示），模型工具也不受这个开关限制。

### 识别后发不发图片

`image_mode` 控制识别成功时随文字一起发出的图片，四档：

- `all`（默认，界面上是「开启」）：图片请求发裁剪图，录音请求发声谱图；
- `crop`（仅照片）：只发图片请求的裁剪图，录音只回文字；
- `spectrogram`（仅频谱图）：只发录音的声谱图，图片只回文字；
- `off`（关闭）：只回文字，不生成任何图片，省流量也省 CPU。

识别与归档不受影响，只是回复里不带图。看板的设置区是一个四选一的分段按钮，改完立即生效。

### 白名单

群聊与私聊各自独立：

- `group_whitelist_enabled` 打开后，只有 `group_whitelist` 里的群聊可以识别；
- `private_whitelist_enabled` 打开后，只有 `private_whitelist` 里的私聊可以识别；
- 名单支持三种写法：完整会话标识（`aiocqhttp:group:123456`）、会话 id（`123456`）、群号；
- **名单为空且开关打开表示谁都不识别**——这是刻意的语义，避免「填错了就全放开」。

看板的白名单设置区会列出现有群聊与私聊，点一下就能加进名单、再点一下移出。候选来自两处：适配器能列出
群/好友的（例如 OneBot）走实时接口，列不出来的（`qq_official`、`wechat_native`）从会话历史里读。
`wechat_native` 每个发言人各有一条会话标识，插件会归并到群本体再列一次，并按群号向本机服务
查一次群名，所以同一个群只会出现一行、带名字。

### `/识鸟状态`（仅管理员）

```
鸟类识别后端
状态：在线（对接官方接口时显示「官方」）
版本：0.1.0
后端队列：0/32
后端负载：ok
内存：插件 96.4 MB，系统 2143.8 MB / 7987.1 MB（27%）
模型：birdnet_v3_fp16、fastvit（ok）
本插件：排队 0，处理中 0
归档：待打包 1.2 MB，已归档 48.7 MB，批次 6
名称库：11587 条
开关：自动回复开，群白名单关，私聊白名单关
```

非管理员触发会收到「该指令仅限管理员使用。」。内存一行来自 `psutil`（AstrBot 已自带该依赖），
取不到时显示「内存：暂不可用」；模型名来自 `model_names` 配置并会与后端 `healthz` 上报的字段合并。

## 管理看板

插件自带一个独立页面 `views/dashboard/index.html`，在管理面板的插件详情里以「识鸟看板」出现
（标题来自 `.astrbot-plugin/i18n/` 下的 `zh-CN.json` / `en-US.json`，跟随界面语言切换）。
页面数据来自插件自己注册的三个 Web API（`/astrbot_plugin_birdid/overview`、`/settings`、`/chats`），
通过 AstrBot 的插件页面桥接调用，不依赖管理面板的内部路由。

- **KPI**：总识别次数、成功率、平均耗时与 P95、并发占用、插件内存、后端状态；
- **图表**：每日识别量、结果分布、近 24 小时趋势、常见鸟种排行；
- **运行状态**：后端在线 / 官方 / 离线（拿不到 `/healthz` 但 `quota` 有应答即「官方」）、本插件排队与处理中、系统内存占用、名称库条数与归档开关；
- **设置**：页面里只放**开关**和**选项**——自动回复、归档、群聊白名单、私聊白名单是开关，
  识别后发送图片是四选一，两份白名单是同屏点选的多选列表（候选来自机器人已加入的群与已有私聊）。
  改动**点一下就保存**，右上角会显示「保存中…／已保存 HH:MM:SS」，没有单独的保存按钮；
  保存成功后立刻写回插件配置并作用到运行中的对象，不用重启 AstrBot；
- **不在页面里的参数**：需要填数字或文本的项（后端地址、并发、超时、`class_code`、`api_area`、
  `did`、`model_names`、归档天数与体积等）不放进看板，仍在管理面板的插件配置或
  `config/astrbot_plugin_birdid_config.json` 里改；这些值改完同样即时生效，慢循环（归档整理间隔）
  在下一轮读取时生效。

## 输出示例

```
识别结果：鸟类（97.1%）
1. 麻雀 / Eurasian Tree Sparrow / Passer montanus  96.4%
2. 山麻雀 / Russet Sparrow / Passer cinnamomeus  2.1%

耗时 218 ms
```

一张图里有多只鸟时，每只鸟各占一组：先给那一组的「识别结果：鸟类（置信度）」，下面列它自己的
候选。画面里没有鸟时，这一行会写成「识别结果：未检测到鸟类。」。

图片回复只附**置信度最高**那个目标的裁剪图，其余目标只出现在文字里；录音的回复结构相同，
只是标题行没有百分比，并附一张声谱图。这两种图片都受 `image_mode` 控制，关掉后回复只剩文字。

## 配置

在 AstrBot 管理面板的插件配置里填写，全部有默认值。带开关和选项的几项也能直接在识鸟看板里改
（见上一节），需要填数字或文本的项只在配置文件里：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `backend_url` | `http://127.0.0.1:8080` | 后端地址 |
| `api_key` | 空 | 后端要求鉴权时填；留空则不发送 |
| `api_key_header` | `api_key` | 携带 key 的请求头名 |
| `max_in_flight` | `2` | 本插件同时处理的请求数 |
| `queue_timeout_s` | `20` | 排队等待空位的最长时间，超时回「有点忙」 |
| `backend_concurrency` | `4` | 与后端之间的并发上限 |
| `request_timeout_s` | `30` | 单次识别的超时时间（秒） |
| `ffmpeg_path` | 空 | 留空则用 `PATH` 里的 `ffmpeg` |
| `auto_reply` | `true` | 附件是否自动识别 |
| `archive_enabled` | `true` | 是否落盘归档；关闭即阅后即焚 |
| `image_mode` | `all` | 识别后发图：`all` 全部 / `crop` 仅照片 / `spectrogram` 仅频谱图 / `off` 关闭 |
| `group_whitelist_enabled` | `false` | 群聊白名单开关 |
| `group_whitelist` | `[]` | 群聊名单 |
| `private_whitelist_enabled` | `false` | 私聊白名单开关 |
| `private_whitelist` | `[]` | 私聊名单 |
| `class_code` | `B` | 懂鸟 `class` 字段，B 鸟类 / M 哺乳 / A 两栖 / R 爬行 / F 鱼类，可组合 |
| `api_area` | 空 | 默认地区码（消息里的地点优先） |
| `did` | 空 | 懂鸟 `did` 设备标识，字母数字，最长 40 位 |
| `model_names` | 空 | 状态回复里显示的模型名，多个用顿号分开 |
| `retention_days` | `7` | 归档保留天数 |
| `archive_max_mb` | `2048` | 归档总体积上限（MB） |
| `archive_interval_s` | `900` | 归档整理间隔（秒） |

`max_in_flight` 与 `backend_concurrency` 是两道闸：前者限制聊天侧积压，后者限制插件对后端的
连接数。后端本身还有自己的队列，队列打满时会回 `server busy`，插件据此立刻返回繁忙提示。

### 出错时用户看到什么

| 情况 | 回复 |
| --- | --- |
| 会话不在白名单里（指令或工具） | `这个会话没有开启鸟类识别。` |
| 指令后面没有跟图片或录音 | `请附上一张图片或一段录音，也可以引用一条包含图片或录音的消息。` |
| 本插件排队超过 `queue_timeout_s` | `现在有点忙，请稍后再试。` |
| 后端拒绝连接、返回非 200 或协议码异常 | `识别服务暂时不可用，请稍后再试。` |
| 后端在 `request_timeout_s` 内没给结果 | `这次识别超时了，请稍后再试。` |
| 图片/录音无法解码（例如损坏的文件） | `这段附件无法读取，请换一张图片或一段录音。` |
| 未预料到的内部错误 | `识别过程出错了，请稍后再试。` |

每条失败原因都会写进插件日志（日志里带后端地址或异常类型，但不是给聊天里的人看的），
聊天回复里不会出现堆栈、地址或模型信息。

## 数据与隐私

- **不长期保留对话**：每条请求的临时文件写在系统临时目录下的独立子目录，回复发完就删除。
- **归档可关闭**：`archive_enabled` 关掉后不写任何媒体，只有内存里的计数；打开时识别成功的图片/录音、
  置信度、检测框、地点名和处理耗时写进 `data/plugin_data/astrbot_plugin_birdid/bird_archive/`，
  按 `retention_days` 与 `archive_max_mb` 自动轮转，过期批次直接删除。
- **不落敏感字段**：归档写入前会剥掉绝对路径和控制字符，`api_key`、`token`、`password` 一类
  字段整个丢弃。
- **统计只在内存**：看板的计数器不落盘，插件重启即清零。
- **回复不含内部信息**：不出现模型名、设备名、路径、后端地址或任何堆栈。

## 名称表

`bird/data/bird_names.tsv.gz` 是「归一化学名 → 中文名 → 英文名」的 gzip TSV，11587 行，
约 200 KB。来源与许可见 [NOTICE.md](NOTICE.md)。学名在查表前会归一化（小写、下划线转空格、
压缩空白），所以 `Passer_montanus`、`passer  montanus` 都能命中同一行。

图片分类器报告的物种名是英文俗名而不是学名（例如 `Cerulean Kingfisher` 会被写成
`Small Blue Kingfisher`），所以插件加载时还会建反向索引：先按归一化学名查，查不到再按归一化
英文名查。归一化会抹平大小写、下划线、连字符和撇号差异（`Blyths Kingfisher` 与
`Blyth's Kingfisher` 视为同一行）。

`bird/data/bird_aliases.tsv.gz` 是补充别名表（964 行，约 19 KB）：把分类器里那些与名录拼写
不一致的类名，按「分类器类序号 → 名录学名」映射到主表的行。别名表只用已有键的空位，
永远不会覆盖主表已有的条目。

名称表缺失或损坏不会让插件失效：查不到的学名会回退显示后端返回的原文。

## 开发

```bash
pip install -r requirements-dev.txt   # 运行依赖 + pytest / pytest-asyncio / ruff

ruff check .
ruff format --check .
python -m pytest tests -q
```

`tests/test_main.py` 需要 AstrBot 本体才能导入，在纯开发环境里会自动跳过；
在装了 AstrBot 的环境里跑，全套 271 个用例都会执行。

代码结构：

```
main.py              AstrBot 入口：识鸟指令、LLM 工具、管理员命令、看板 API
views/dashboard/     识鸟看板页面（单文件 HTML + 原生 JS）
.astrbot-plugin/     插件页面的 i18n（看板标题的中英文）
bird/client.py       懂鸟 v2 协议客户端（提交、轮询、错误码、百科、配额）
bird/media.py        从消息里取媒体、图片规范化、音频转码
bird/service.py      一次识别的编排：并发闸、裁剪图、声谱图、归档
bird/render.py       裁剪与声谱图绘制（只依赖 Pillow 与 numpy）
bird/names.py        学名到中英文名的查表
bird/regions.py      地点文本到后端地区码
bird/format.py       回复文本与状态文本渲染
bird/archive.py      归档暂存、打包、轮转（可整体关闭）
bird/settings.py     设置快照与访问策略（白名单语义）
bird/stats.py        看板用的有界计数器
bird/hostinfo.py     进程与主机内存、负载读数
bird/dashboard.py    看板三份文档的组装（纯函数）
bird/data/           名称表与别名表
tests/               单元测试
```

## 已知限制

- 后端只解 16 bit PCM WAV，其它格式一律先用 `ffmpeg` 转成 32 kHz 单声道，没装 `ffmpeg`
  时录音识别不可用（图片识别不受影响）。
- 一条消息只识别第一个图片或第一个录音，多附件时按图片优先。
- 地点先验只能映射后端 `regions` 表里有的地区码，其它省份不带先验。
- 分类器有 11 个类名对不上任何名录条目（多为杂交种或分类学新拆分），这些条目的中文名
  留空、只显示后端返回的英文名。
- 白名单按会话标识匹配；适配器改名（例如换了平台实例 id）后需要重新勾选。
- `wechat_native` 的群名是按群号向本机服务现查的，服务没起时该行仍然是空名字，但标识可用。
- 官方接口的配额探测在拿不到 `/healthz` 时触发，探测结果缓存 30 秒，不会每次回复都多打一次。
- 指令别名是固定的十几种说法，写法不同（例如加字、换语气）会落到 LLM 工具；想加别名改
  `main.py` 里的 `IDENTIFY_ALIASES`。
